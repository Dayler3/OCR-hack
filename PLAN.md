## 1. Резюме проекта

Автономный комплекс, который принимает скан/фото документа (JPG, PNG, PDF) + текстовый вопрос студента, распознаёт текст, заполняет карточку реквизитов (пропуски = `«не найдено»`), проверяет документ по «Положению о приёме документов» и выдаёт один из 3 детерминированных ответов со ссылкой на пункт регламента.

**Жёсткие ограничения:**
- Никаких внешних облачных LLM/API (GigaChat, OpenAI, YandexGPT и т.п.) — всё локально.
- Запуск на CPU обычного ПК или в бесплатном Colab (CPU / 1×T4).
- OCR только открытый: PaddleOCR (PP-OCRv4, основной), EasyOCR/Tesseract — резерв.
- 3 типа документов с фиксированными атрибутами; подпись/печать — только `есть`/`нет`.
- Формат дат в полях — `ДД.ММ.ГГГГ`.
- **Датасет задачи:** Открытый бенчмарк `MTSAIR/MWS-Vision-Bench` (MTS AI / Hugging Face). Аннотации в формате `metadata.jsonl` (пары `file_name` + `question`, задачи `KIE`, `Grounding`, `Reasoning VQA`).

**Состав сдачи:** публичный git-репозиторий + README, `results.json` по спецификации жюри, видео-демо ≤ 3 мин, презентация ≤ 10 слайдов.

### 2.2. Пробелы, которые ТЗ не закрывает (учтено в плане)

1. **Нет `pipeline.py`** — оркестратор, хотя `batch_eval.py` импортирует `app.core.pipeline`. Ключевой модуль, его надо спроектировать первым.
2. **Нет `classifier.py`** — бонусное автоопределение типа документа (в дереве §7 отсутствует).
3. **Нет источника `regulations.json`** — «Положение» вуза нужно распарсить в нумерованные пункты + связку `doc_type → обязательные поля + пункт правила`.
4. **Ветка «Ответа нет» (NO_INFO)** — в ТЗ описан только валидатор полей; логика «вопрос не покрыт Положением» не спроектирована (ответственный этап — RAG-ретривер + порог релевантности).
5. **Координаты BBox после препроцессинга** — deskew/апскейл меняют геометрию. Решение: фронт показывает **препроцесснутое** изображение, а не оригинал; либо обратное преобразование bbox. Иначе подсветка «поедет».
6. **Многостраничные PDF** — поле может быть на любой странице; в ответе нужен индекс страницы рядом с bbox.
7. **Нет инфраструктуры:** `git init`, `.gitignore`, тесты, `vite.config.ts`/`tsconfig.json`, запуск фронт+бэк одной командой, кэш моделей PaddleOCR и rubert-tiny2 (иначе каждый запуск тянет сотни МБ).
8. **Спецификация данных и `results.json`** — работаем по стандарту `MTSAIR/MWS-Vision-Bench` (`metadata.jsonl`), валидируем на сплите бенчмарка; финальная проверка ключей `results.json` по README организаторов при закрытой проверке.

## 3. Архитектура и поток данных

```
Файл (JPG/PNG/PDF) ──► preprocessor ──► ocr_engine (PaddleOCR, bbox+текст по страницам)
      + вопрос                              │
      + тип (ручной/авто)                   ▼
                                   classifier (бонус: якоря + скоринг)
                                            │
                                            ▼
                     extractor (YAML-схема: NER Natasha / regex / options / anchor)
                                            │
              cv_detectors (печать/подпись) │
                                            ▼
                     rag_engine (BM25 + rubert-tiny2) ──► пункт Положения / NO_INFO
                                            │
                                            ▼
                     validator (rule engine) ──► 3 ветки ответа
                                            │
                                            ▼
                     pipeline.py собирает AnalyzeResponse ──► API / frontend / batch_eval
```

**Принцип разметки координат:** препроцессор возвращает финальное изображение (после deskew/апскейл) + признак поворота; OCR и все bbox живут в координатах этого изображения; фронт получает его же как подложку. Это устраняет проблему §2.2-5.

## 5. Контракты (зафиксировать до кода)

### 5.1. API

`GET /api/schemas` → список типов документов из YAML (для Select на фронте + автоопределение).

`POST /api/analyze` — multipart: `file`, `question`, `doc_type?` (null = автоопределение):

```jsonc
{
  "document_type": "study_certificate",
  "document_name": "Справка об обучении",
  "classifier_confidence": 0.87,          // бонус-режим
  "pages": [                               // препроцесснутые страницы (base64 PNG) — подложка для BBox
    { "width": 1654, "height": 2339, "image_b64": "..." }
  ],
  "fields": [
    { "key": "fio", "label": "ФИО студента", "value": "Иванов Иван Иванович",
      "bbox": [120, 340, 890, 372], "page": 0, "source": "ner_person" }
  ],
  "verdict": { "status": "MISSING_FIELDS", "text": "Не хватает: ...", "rule_source": "п. 3.4 Положения" },
  "timings_ms": { "preprocess": 210, "ocr": 3800, "extract": 140, "rag": 90 }
}
```

`status` ∈ `OK | MISSING_FIELDS | NO_INFO` — ровно три ветки из §4 ТЗ, шаблоны текста — дословно из ТЗ.

### 5.2. `regulations.json`

```jsonc
{
  "rules": [
    {
      "rule_id": "п. 3.4 Положения",
      "text": "Справка об обучении должна содержать ...",   // для BM25/эмбеддингов
      "doc_types": ["study_certificate"],
      "mandatory_fields": ["fio", "university", "study_direction", "study_form",
                           "study_period", "doc_number_and_date", "stamp_and_signature"],
      "topics": ["справка об обучении", "подтверждение обучения"]   // якоря релевантности вопроса
    }
  ]
}
```

## 7. Риски и меры

| Риск | Вероятность | Мера |
|---|---|---|
| PaddleOCR не ставится/медленно на CPU Windows | средняя | Флаг `OCR_ENGINE` + резервный движок (Tesseract) с тем же интерфейсом `ocr_engine`; проверка в фазе 0, не в день 4 |
| Regex из ТЗ не матчат реальные сканы | высокая | Юнит-тесты на фикстурах с дня 2; итеративная правка YAML (ради этого и YAML-архитектура) |
| BBox «уезжает» после deskew | высокая | Показ препроцесснутого изображения как подложки (решение зафиксировано в §3) |
| Медленный rubert-tiny2 на CPU | низкая | Модель ~120 МБ, инференс быстрый; прогрев в startup, кэш эмбеддингов правил |
| Спецификация `results.json` изменится | средняя | Структура ответа изолирована в одном месте `batch_eval.py`; переверификация при выдаче датасета |
| Слияние фронт/бэк в последний день | средняя | Контракты §5 фиксируются в фазе 0; фронт можно делать против mock-данных с дня 2 |
| Ветка NO_INFO не отличается от MISSING_FIELDS | средняя | Отдельные тесты фазы 3: вопрос вне тем Положения → строго шаблон «Ответа нет» |
